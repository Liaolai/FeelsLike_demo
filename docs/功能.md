# FeelsLike 完整功能说明

版本日期：2026-11-15。基准：已发布第五版，源码提交 `bee82295d03d6d143a9c95021065ec114204fc39`。本文是当前功能快照，取代旧文档中按开发轮次追加的历史描述。

体验链接：https://westlake-climate-fieldlab.dreamystingray4.chatgpt.site

## 1. 产品要解决的问题

面向西湖户外游览，把区域天气、当前活动、现场测温和个人冷热感受放在同一个页面里，让使用者在游览前和游览中获得补水、休息、避暑、保暖与穿搭提示，并理解气温和体感的区别。

产品采用“环境层—个体层—指标层—决策层”：环境层为地图、地形、天气；个体层为一个可操纵人物及用户填写的信息；指标层为气温、预报体感、现场参考体感、静息能量；决策层为行动卡片、穿搭、人物气泡和定时提醒。当前个性化采用明确规则，没有训练个人机器学习模型。

## 2. 页面与使用流程

1. 打开网页，天气与三维场景分别加载。
2. 选择人物，在沙盘中移动，或选择景点跳转、沿路漫步。
3. 查看附近区域天气、未来24小时预报及行动建议。
4. 可选填写身体、健康、现场环境测温、冷热感受和心情。
5. 查看更新后的建议和穿搭计划；需要时开启页面内定时提醒。
6. 一键切换温度彩图，查看区域气温或预报体感的空间表达。

无需账户登录。个人记录保存在当前浏览器，设备之间不自动同步。

## 3. 数字沙盘与真实空间

| 功能 | 当前行为 |
|---|---|
| 地图底层 | 用户提供的西湖 OSM 道路、水域、岛屿、建筑轮廓 |
| 地形 | Copernicus GLO-30 栅格，三角插值；显示时垂直放大1.6倍 |
| 道路 | 依真实道路形状铺设，沿地形裁切并覆盖共享节点接缝 |
| 道路查询 | 点击道路高亮并显示名称；原始数据无路名时显示道路类型 |
| 路网 | 基于 OSM 可步行节点与边，不为连接岛屿而添加虚构步行道路 |
| 建筑 | 按轮廓生成，缺少高度时采用示意高度 |
| 树木 | 树干与树冠；在道路两旁和绿地布置，并避开水域、建筑和路面 |
| 湖水 | 波纹与反光，动画参考预报风速；低动态模式冻结 |
| 雷峰塔 | 定制八角五层塔形，含台基、塔身、屋檐、栏杆、窗格与塔刹 |
| 码头 | 九处码头有古风小屋、木平台、立柱和牌匾 |
| 二维降级 | WebGL 不可用时保留可点击移动的二维地图 |

湖水与树木用于场景表达，没有计算水动力或树荫降温。此前空间审计统计为2,545条道路，其中519条有原始名称；这些数字对应当前打包数据，不代表景区全部道路均已测绘。

## 4. 景点与交通地点

支持位置标签、选择跳转和沿路漫步，共18个目标。

沿湖景点：断桥残雪、苏堤春晓、雷峰塔、曲院风荷、花港观鱼、柳浪闻莺、平湖秋月、孤山、三潭印月。

游船码头：二公园、五公园、少年宫、中山公园、岳庙、花港、钱王祠、手划船、三潭印月码头。

直接跳转是浏览地图的快捷操作；沿路漫步遵循可步行路网。三潭印月岛屿与陆地网络分离，不把跳转表现成真实步行跨湖。

## 5. 人物、操作与视角

- 全场景只有一个受控人物，取消多个同行者。
- 接入用户原始包中的九个真实 GLB，选择界面使用对应缩略图。
- 每个模型保留41关节、六段动画；页面连接待机、走路、跑步，其他动作保留为素材。
- 模型统一约1.7米高，只加载选中模型；切换时保留当前位置、活动和个人记录。
- 支持第三人称跟随、人物眼平视角、全景；拖动转向、滚轮调距。
- WASD、方向键与屏幕按钮控制；键盘松开即停止，失焦或隐藏页面暂停手动移动。
- 屏幕方向按钮为短距离步进；自动移动只通过“沿路漫步”开启，可停止。
- 活动可选择步行、休息、跑步，参与建议及动画选择。

动画中的水平根位移已移除，真实场景位移由路网控制。移动展示经过提速，不输出真实行程时间。人物外观不推断用户年龄、性别或健康。

## 6. 天气数据与仪表盘

主气象来源为 Open-Meteo Forecast API。预设西湖北岸、南岸、西岸三个请求位置；请求当前天气和未来三天逐时数据，页面展示接下来24小时。

显示项目：气温、区域预报体感、相对湿度、风速、阵风、短波辐射、紫外线、降雨概率，以及来源、有效时刻和连接状态。单位包括°C、%、m/s、W/m²。

第五版优先由设备直接访问公开天气接口，10分钟缓存；失败时尝试站点服务端接口。页面每5秒重新生成/更新人物报告，不是每5秒向上游索取新天气。429限流遵循 Retry-After 并保存等待状态。

气象有效时刻超过90分钟判为过期；失败后可保留旧数据，但不改写原有效时刻。没有天气时显示缺失，不补模拟数值。

数值显示到0.1°C是显示精度，不是测量误差或空间精度。当前自动选模，未锁定单一模型分辨率；此前三处请求返回同一个实际格点。数据属于区域模型预报，不是手机温度传感器或街道现场实测。

## 7. 温度彩图

一键在3D沙盘和二维温度彩图间切换，可选气温或区域预报体感。

- 保留道路、建筑与地点标签，可点击道路或位置。
- 支持拖动、双指缩放、缩放按钮及全图复位。
- 固定色标−10至40°C，提供常规及色觉友好配色。
- 按服务实际返回格点坐标去重，一个格点覆盖时保持同色；多个格点使用最近样本。
- 缺失、过期、时间异常的数据不用于着色。
- 现场测温与主观感受不扩散为整张地图温差。
- 切换到彩图时暂停3D渲染，切回保留人物状态。

该图表达区域气温/预报体感，没有实现UTCI、地表温度、街道遮阴或微气候求解。

## 8. 身体信息与能量展示

可选填写身高、体重、年龄及公式使用的性别系数，可保存或清除。采用 Mifflin–St Jeor 估算静息能量，显示 kcal/day 与对应 W；未选择性别系数显示区间。参考年龄19—78岁，范围外不自动套用。

当前结果用于身体消耗展示，没有直接修改体感、健康阈值、补水量或提醒间隔。

## 9. 健康情况与个性化照护

可选健康、感冒、心脏病、高血压、糖尿病、肾脏疾病、其他，以及“医生要求限制饮水”。其他可填写最多200字；健康与其他情况互斥。

健康资料会实际影响行动文案、穿搭附加提示和已开启的定时提醒：感冒优先休息；慢性疾病叠加热条件时增加阴凉休息并缩短问候间隔；限制饮水时改为休息提示，饮水依已有医生安排。

这是自报信息入口，没有接入心率、血压、体温、疾病检测、手表或蓝牙传感器，也没有生成疾病风险分数。

## 10. 现场测温与主观冷热

现场测温：手工记录环境气温，可选湿度与参考10米风速。记录关联沙盘人物位置，30分钟、100米内有效；界面单独显示现场气温和可计算的现场参考体感。未启用手机GPS，需要先把人物放到对应位置。

主观冷热：选择偏冷、刚好或偏热，可清除。反馈在同一活动下两小时内参与建议；改变活动或过期后停用。它改变提醒和穿搭，不直接给气温加减数值。

## 11. 行动、补水与提醒

行动卡片根据热、风、冷、活动、雨、UV及个人资料给出当前建议，多个环境原因可以同时保留。没有个体历史也能显示通用“记得带水，注意休息哦”。

可点击“已补水”记录时间，或切换休息。定时提醒需主动开启：普通为30分钟；指定慢性疾病与热条件同时存在时为15分钟。根据健康情况，提示内容可从饮水改为休息。它是产品问候节奏，不是医学安全时长或饮水处方。

手机端目前只有页面内提示。网页关闭后不工作；锁屏或切后台可能被系统暂停。尚无 Service Worker、系统通知、Web Push或可靠后台调度。

## 12. 情绪与人物头顶气泡

心情可选开心、平静、疲惫、烦躁。人物头顶优先显示有效天气/测温引起的高温或低温提示及emoji；舒适时显示自报心情，或约25秒轮换想吃鱼、跳舞、听歌、看风景等展示想法。

低动态模式冻结随机轮换。温度相关情绪文案是条件式建议，没有根据温度自动判断用户真实情绪，也没有情绪识别模型。

## 13. 穿搭建议

按有效参考温度分六档，叠加风、雨、UV、跑步、主观冷热和感冒情况。当前真实GLB采用原有固定服装贴图；“记下这套穿搭”保存建议计划，不执行真实服装换装。无有效温度时不能保存基于天气的计划。详细档位见《算法.md》。

## 14. 手机、语言与无障碍

支持中文/英文切换。标准模式、色觉友好模式、彩色高对比模式与低动态设置；低动态减少水面、人物等动画。文字和底色对比已调整，正文/提示约14—16px，输入16px，地图标签14px。

手机端隐藏地图大标题及长说明，地点与视角工具折叠，保留模式切换和方向操作；天气指标采用两列，预报按宽度排版。尚未声称通过正式无障碍认证或所有手机性能验收。

## 15. 数据保存与服务接口

| 数据 | 保存/使用位置 |
|---|---|
| 语言、配色、人物选择、提醒开关 | 当前浏览器 localStorage |
| 健康、其他自填、身体、现场测温、心情、饮水、穿搭计划 | 当前浏览器；无跨设备同步 |
| 公开区域天气及限流等待信息 | 浏览器天气缓存；服务端另有缓存 |
| 服务端回退请求 | 仅人物ID、虚拟地图坐标、活动、近期冷热反馈等允许字段 |
| 天气提供方请求 | 预设三个区域坐标与气象字段；不发送上述健康/身体资料 |

接口：`GET /api/health`服务状态；`GET /api/diagnostics`服务端天气诊断；`POST /api/telemetry`人物天气报告；`GET /api/crowd`客流接入状态。本地 Node 保留 SSE 能力，但第五版主界面默认采用设备直连与5秒轮询报告，不能把旧版SSE描述成当前主链路。

## 16. 已发布、未接入及核验状态

已发布第五版：真实GLB人物、设备直连天气与缓存、3D/彩图、路网交互、资料入口和规则提醒。此前60项自动测试通过，本地浏览器确认真实天气、模型与松键停止。

线上曾确认服务端上游429；第五版部署成功，但线上天气恢复尚未完成确认。不能把“发布成功”写成“所有手机均已恢复数据”。

待接入：tjweather的有效 key/subscriptionId、真实今日游客人流、GPS、自动传感器、账户同步、可靠后台推送。客流模块目前显示暂无数据并提供景区公告入口，不生成估算人流。尚未验证提醒是否实际改善游客行为或健康结果。

数据来源：OSM（ODbL）、Copernicus GLO-30、Open-Meteo；渲染使用Three.js r160与Meshoptimizer。地理与第三方资产的许可说明见README和对应资源文件。原始用户模型随工作包保留，团队对外使用时应一并确认原资产授权。
