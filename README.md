# FeelsLike · Westlake Climate Fieldlab

独立网页工程。未修改 `feelslike-sandbox`、`1114微气候智能体`、`urban_heat_grid` 或 WorkBuddy 的任何文件。

## 运行

安装 Node.js 22+ 后，在本目录运行 `npm start`，访问 http://127.0.0.1:8791 。无需安装第三方依赖。Windows 也可双击 `start.cmd`。

`npm test` 验证后端规则与数据边界；`npm run build` 打包为可部署的 Cloudflare Worker（全部资源内嵌，离线空间数据约 2 MB）。

## 部署

### GitHub Pages（静态预览，已自动同步）

`.github/workflows/pages.yml` 在 `public/**` 或 `scripts/build-pages.mjs` 变化时，自动生成相对路径副本并推送到 `gh-pages` 分支。Pages 源固定指向 `gh-pages`，因此构建失败时线上仍是上一版，不会整站挂掉。

改完 `public/` 无需任何手动操作。本地复现构建：`node scripts/build-pages.mjs`，产物在 `.pages-dist/`（已 gitignore）。

源码使用根路径绝对引用（`/assets/...`），而 Pages 项目页在子路径 `/<repo>/` 下，所以构建期必须相对化——这一步只发生在构建产物里，不影响本地运行与 Render 部署。

### Render（完整功能，含健康 AI）

仓库内 `render.yaml` 已备好：Render 控制台 New → Blueprint → 选择本仓库即可。

服务绑定 `0.0.0.0` 并读取 `process.env.PORT`（已处理）。健康 AI 依赖 `DEEPSEEK_API_KEY`，在控制台环境变量中填写；不填也能正常启动，此时 `/api/health-advice` 返回 503 `not_configured`，其余功能不受影响。

免费实例 15 分钟无访问会休眠，冷启动约 30–60 秒。

## 主要功能

- 真实 OSM 路网、西湖多边形及岛屿、真实 Copernicus DSM 地形、OSM 建筑轮廓。
- 默认第三人称跟随；可切换人物眼平视角、全景。WASD / 方向键 / 屏幕按钮移动，拖动转向，滚轮调距。景点导航沿 OSM 可步行网络寻路；地图只表达数据中的可通行性，不替代景区现场指示。
- 一个可操纵人物、九种可选外观，仪表盘随位置和活动更新。不请求 GPS，不训练个人模型，不生成虚拟体感评分。
- Open-Meteo 三点 current 与 hourly 气象，10 分钟缓存。显示气温、预报体感、湿度、风、阵风、紫外线、短波辐射、降雨概率及未来 24 小时预报。每项数值有来源和有效时间。
- 本地 Node 服务每 5 秒后台计算，并通过 SSE 推送；每条 SSE 连接只包含该浏览器提交的虚拟人物。部署的 Worker 由浏览器每 5 秒 POST 驱动计算，页面关闭后不持续计算或提醒。
- 冷启动通用补水、休息、天气注意事项；本机保存补水与体感记录。页面内休息/饮水提醒需主动打开，间隔按健康情况和冷热感受为15或30分钟。提醒规则可在“数据与方法”审阅，非医学阈值或官方预警，不输出安全停留时长。
- 中英文、色觉友好、高对比彩色、低动态/光敏设置；WebGL 不可用时降级为可点击移动的二维 OSM 地图。

## 真实数据边界

“实时”指持续获取气象模型当前时段输出，不是现场传感器秒级实测。人物选择最近请求点，不把区域预报虚构成每条街道实测。紫外线、辐射、降雨概率取最近逐时值。数据有效时刻超过 90 分钟明确标为过期；上游失败不生成模拟数值。

**尚未接入：真实今日客流，以及需要 key/subscriptionId 的 tjweather。** `/api/crowd` 明确返回 `available:false`。不把地图热度当作客流。

三维显示重采样地形并作 1.6 倍垂直夸张；人物与树木为示意符号，树木布置于道路两侧及 OSM 绿地，整片树冠避开路面，不是树木测绘；缺失建筑高度用 4m 示意。未解析或转换原 `.max` 模型，未引入学习曲线、训练模型或虚拟用户评分等模拟器功能。

## 延续问诊的行动问题

原问题：如何将现有材料实现为完整实时数字沙盘、交互人物和人物仪表盘。

实际要解决：首次使用、没有个人体感历史的游客，也能在出行或游览中提前获得可理解的天气与行动信息。

已确认：用户要先制作；以真实地图、人物跟随和后端体感为主；不加入多余个人模型。现有目录有可复用空间资料和原型。

未验证假设：实际游客会因提醒改变补水、休息或出发时间；区域模型足以支撑所需提醒粒度；授权客流源可获得。

关键变量：气象与客流可用性、模型空间精度、提醒时机、现场用户是否采取行动。

下一步可检验的问题：在一次真实西湖出行中，新用户能否根据人物仪表盘与提前提示，完成一次补水或休息行动，并理解提示的气象依据？

## 路网、树木与代谢核验

道路按不超过 2.5m 加密，路面与地形使用相同三角插值，原节点增加接缝覆盖。树木使用树干与树冠两组实例化网格，整片树冠离道路边缘至少 1.1m，避开建筑与水域；新增道路两侧树列为示意绿化，非测绘实景。路网不添加虚构连接：八个大陆景点连通，三潭印月所在岛屿独立。详见 verification/spatial.json；node scripts/audit_spatial.mjs 可重跑。

身体信息与静息能量：每位虚拟人物可录入身高、体重、年龄、性别公式系数。Mifflin–St Jeor（1990，PMID 2305711），不指定系数显示区间；参考年龄19–78岁，范围外不自动套用。不用于诊断、饮水量或热阈值推算。身体信息只在浏览器保存和计算，不通过 SSE 或 API 上传。

真实气象核验：node scripts/check_api.mjs，报告 verification/api.json。界面“实时接口状态”调用 /api/diagnostics 查询 HTTP、最近成功时间、字段数量、三点有效时间和实际格点数量。当前 Open-Meteo 三个请求点落在同一实际预报格点，不宣称街道级实测差异。tjweather 无有效凭证，客流源未接入，两者如实披露。


## 配色、路面与情绪更新

标准模式的地图标题、景点标签、导航按钮均使用明确的深色文字与浅色底板；相机按钮的选中状态不再误作用于整个沙盘。高对比模式使用深蓝、奶油色、琥珀色道路和蓝色湖水，保留颜色；色觉友好与减少动态可独立选择。

路面三角形沿地形网格及其对角线裁切，避免顶点在地表上、三角形内部却穿入地形的问题。最新全图审计覆盖 2,545 条道路、725,614 个路面三角形，顶点与三角形重心未检出埋入地形，树冠与路面冲突为 0。该检查不会把原始 OSM 中分离的岛屿路网虚构连接。

新增人物心情选择：开心、平静、疲惫、烦躁，只保存在本机，不上传后端。头顶对话框优先显示当前有效预报的冷热提示（气温或预报体感 ≥32°C；气温 ≤10°C 或预报体感 ≤5°C），这些为产品触发规则，不是官方预警。未触发时显示自报心情，或每 25 秒轮换的鱼、跳舞、听歌、看风景等展示想法；减少动态模式冻结轮换。温度相关的情绪建议采用条件表述，不根据天气推断真实心情。

本轮验证：23 项测试通过；标准模式景点跳转、高对比彩色、心情选择与气泡已在本地浏览器确认，无浏览器控制台错误。当前修改已本地构建，尚未发布到线上。

## 天气限流修复与GLB人物接入

线上诊断已确认原气象缺失为Open-Meteo HTTP429限流。网页现在优先由设备直接读取公开天气API，缓存10分钟，使用同一套字段验证与冷热规则；失败时保留原天气有效时间并尝试服务端取数，数据过期仍标为过期。429遵循Retry-After，退避状态跨刷新保存，避免每5秒请求上游。天气加载与3D人物加载并行，温度无需等模型完成。

已接入用户新增的9个GLB模型，原始包为工作区根目录的9个角色_模型+骨骼+6动作_20261115.zip。优化副本保留41关节和六段动画，不简化网格，使用Meshopt压缩与512px WebP贴图，每个约0.6–0.7MB；只加载当前选择的一个角色。已连接待机、走路和跑步动作；走跑动画移除水平根位移，地图位置由OSM路网控制。身高归一为1.7m，原资产包和参考图片未修改。人物服装使用原GLB贴图，穿搭模块保存建议计划。

Three.js r160 GLTFLoader与BufferGeometryUtils来自官方仓库，Meshoptimizer为MIT，许可证见public/assets/meshoptimizer-LICENSE.txt。原包校验值和各角色输出大小见verification/avatar-assets.json。

本轮60项自动测试通过，包括9个真实GLB的骨骼/动画/身高、走跑原地化，以及天气缓存、429退避、过期数据和错误数据处理。浏览器已确认真实GLB加载、人物切换保留位置、松开W键后停止、设备直连真实气象；线上发布后再做最终复核。
